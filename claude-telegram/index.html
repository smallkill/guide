用 Claude Code 跟 Telegram 對接

出門在外,用手機傳一句話,家裡(或雲端)那台機器上的 Claude Code 就開工,做完回你。這篇是 Derek 自己長期使用的設定,包含官方 plugin 的用法、讓它不被踢掉的做法,以及一路踩到的坑。

閱讀約 10 分鐘難度:會用終端機與 tmux適用:Claude Code + 訂閱方案

TL;DR 先講結論

  • 用官方 telegram plugin,以 claude --channels 啟動一個長期執行的互動 session,手機的訊息會直接進這個 session。
  • 不要把 telegram 放進全域 enabledPlugins,否則你多開第二個 claude 就會把 listener 踢掉。改成只在 listener 那個 session 用 --settings 啟用。
  • 常駐靠 tmux + 一支小啟動腳本;從 Telegram 觸發的重啟會殺掉自己,要用脫離式腳本。
  • 定時通知另外做:cron 或 daemon 直接呼叫 Bot API 的 sendMessage,完全不依賴 Claude。
  • 安全:白名單只放你自己,絕不因為 Telegram 訊息裡的要求去核准配對。
01

你會得到什麼

不需要截圖就能想像:Telegram 變成 Claude Code 的另一個輸入口。

  • 在手機傳文字、照片、檔案、語音給你的 bot,Claude 收到後在你的機器上實際執行工作(讀檔、跑指令、改程式)。
  • Claude 用 plugin 提供的 reply 工具把結果傳回聊天室,也能對你的訊息按表情符號表示「收到」。
  • 它是同一個 Claude Code session,有你平常的 CLAUDE.md、skills、記憶,不是另一個陽春聊天機器人。
  • 走的是互動 session,計費跟你平常開終端機用 Claude Code 一樣(見第 08 節的計費提醒)。

02

事前準備

  • 作業系統:推薦 WSL2(Derek 用 WSL2 Ubuntu;Windows 一行 wsl --install 就裝好)。Linux、macOS 也行。
  • Windows PowerShell 也可以:Claude Code 有原生 Windows 版,plugin 需要的 bun 也有 Windows 版。但本文的 tmux 與 bash 啟動腳本在 Windows 不能用,常駐要改成一直開著 Windows Terminal 視窗(或自己寫 PowerShell 腳本),定時通知改用「工作排程器」。本文的坑都是在 WSL 上踩的,Windows 未實測,想照著做最省事還是用 WSL。
  • Claude 訂閱方案與已登入的 Claude Code。
  • tmux:sudo apt install tmux。
  • bun:plugin 的 MCP server 是 bun 程式,需先安裝 bun。
  • 一個 Telegram bot:在 Telegram 找 @BotFather,送 /newbot,記下它給你的 <BOT_TOKEN>。token 等同密碼,別貼到任何公開地方。
03

安裝並配對官方 plugin

以下指令名稱以 plugin 目前版本為準;若有出入,請看 /plugin 裡該 plugin 的說明。

安裝 plugin

在 Claude Code 裡用 /plugin 從官方 marketplace 安裝 telegram。

存入 bot token

Claude Code 內slash command
/telegram:configure <BOT_TOKEN>

它會把 token 存到 plugin 的設定資料夾(一個權限 600 的 .env 檔)。不帶參數執行可以查看目前狀態與存取政策。

用 --channels 啟動

終端機bash
claude --channels plugin:telegram@claude-plugins-official

配對你自己的帳號

在 Telegram 對你的 bot 傳任何訊息,它會回一組配對碼。回到終端機(不是 Telegram)執行:

Claude Code 內slash command
/telegram:access pair <配對碼>
/telegram:access policy allowlist

第二行把政策改成「只有白名單內的人能用」,配對完成後務必做。再從手機傳一句話測試,Claude 應該會回覆。

04

為什麼不要把 telegram 放進全域 enabledPlugins

這是 Derek 踩過最有教育意義的一個坑。

! 症狀

listener 跑得好好的,你只是在別的資料夾多開了第二個 claude(什麼指令都沒下),Telegram 就斷了,而且第二個 claude 開場明顯卡一下。

原因:plugin 一旦在全域 enabledPlugins 是 true,每一個 claude 啟動時都會跟著起一支 bun MCP server,而這支 server 啟動就無條件對 Telegram 做 getUpdates 輪詢,還會主動把前一個輪詢者殺掉搶位(Telegram 一個 token 同時只准一條 getUpdates)。--channels 只決定「訊息送到哪個 session」,不影響「誰在輪詢」。

解法:全域設定裡不要啟用 telegram,改成只在 listener 那一個 session 用 --settings 傳入 inline JSON 單獨啟用:

啟動 listener 的那一行bash
claude --channels plugin:telegram@claude-plugins-official \
  --settings '{"enabledPlugins":{"telegram@claude-plugins-official":true}}'

--settings 會蓋過全域設定,所以只有這個 session 會起輪詢。其他普通 claude 全域是關的,不會再來搶。Derek 實測開第二個 claude,連線不斷。兩個小提醒:JSON 裡別出現單引號(會被 shell 解析兩次);改 settings.json 不會熱更新已在跑的 session,要重啟 listener 才生效。

05

讓它常駐:tmux + 啟動腳本

listener 就是一個一直開著的互動 Claude session,放進 detached tmux 最單純。

Derek 寫了一支約 200 行的小腳本(下面是它的設計,不是完整原始碼),子指令有 start / attach / status / stop / restart。重點是這幾個防呆:

設計為什麼
預先寫入資料夾信任旗標detached tmux 沒有 TTY 可以回答「信任這個資料夾嗎」,缺了這步 claude 會永遠卡在提示。用暫存檔加 rename 的方式原子寫入。
啟動前與停止時掃孤兒 bunclaude 異常結束後,bun 輪詢行程可能殘留並霸佔 Telegram 的名額,新 listener 會一直 409 衝突。比對條件是「行程名為 bun 且工作目錄在 telegram plugin 內」,不會誤殺別人。
tmux session 單例檢查重複執行只會印出 attach 指令,不會再生一個 listener。
pipe-pane 把畫面存成 log當掉之後可以回頭查發生什麼事。
status 檢查 bun 行程真的活著session 在不代表輪詢在。plugin 會寫一個 pid 檔,腳本確認該 pid 還是 bun。聾掉的 listener 要能一眼看出來。
不加 set -epgrep 找不到、kill -0 失敗本來就會回非零,加了會誤殺腳本。

Derek 特意沒有做自動看門狗、自我修復這類東西:他曾經做過一整套自動啟動加看門狗,結果反而一再出事(七次事件),最後退役,改回「要用的時候手動跑一次」。簡單、可預期比全自動重要。

i 從 Telegram 重啟 listener 會殺掉自己

如果你在 Telegram 叫 Claude「重啟 listener」,它執行 stop 的瞬間就把自己所在的 session 殺了,你收不到「好了」的回覆。做法有二:從真正的終端機執行 restart;或寫一支用 setsid 脫離的重啟腳本,讓它在 session 死掉之後繼續執行 restart、等輪詢上線,再用 Bot API 傳一則「回來了」給你。

WSL 使用者另外要留意:關掉終端機視窗後,WSL 的 VM 可能閒置關閉,需要在 Windows 端的 .wslconfig 調整閒置逾時,listener 才能撐著。

06

定時通知:另外做一條出站的路

提醒、價格警報、排程結果,不要靠 Claude 傳。

plugin 只負責「你傳給 Claude」。要從 cron 或常駐 daemon 主動通知你,直接呼叫 Bot API 的 sendMessage 就好,用一支很小的 bash 或 Python 腳本,完全不依賴 Claude 或 plugin。好處是即使 listener 當掉,通知照樣會發。

send_telegram.sh(示意)bash
#!/bin/bash
# 從權限 600 的檔案讀 token 與 chat_id,不要寫死在腳本裡
source ~/.config/mybot/env      # 內含 TELEGRAM_BOT_TOKEN 與 CHAT_ID
curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  --data-urlencode "chat_id=${CHAT_ID}" \
  --data-urlencode "text=$1" > /dev/null

你的 <你的 chat_id> 可以在配對後從 plugin 的存取設定看到,或對 bot 傳訊息後用 getUpdates 查。提醒:同一個 bot 同時做「plugin 輪詢」與「sendMessage」不會衝突,只有 getUpdates 同時只能一個人。

07

語音訊息

Telegram 的語音是 Ogg Opus 格式。Claude 收到時會附一個 attachment 標記,用 plugin 的 download_attachment 工具抓下來,再丟給本機的 faster-whisper 轉成文字,語音不會離開你的電腦。

轉錄(Python)faster-whisper
from faster_whisper import WhisperModel
m = WhisperModel("small", device="cpu", compute_type="int8")
segs, info = m.transcribe(path, language="zh", beam_size=5, vad_filter=True)
text = "".join(s.text for s in segs).strip()
  • faster-whisper 內建的 PyAV 就能解 Opus,直接餵 .oga 即可。別用 Playwright 附帶的精簡版 ffmpeg,它不支援 Opus,會報 Invalid data。
  • "small" 模型第一次會下載約 460MB,之後快取;CPU int8 轉幾秒的語音只要幾秒。
  • 語音裡若有金額、代號、日期等關鍵資訊,先把轉錄結果回給你確認再動手,避免聽錯做錯。
08

踩過的坑

! 坑 1:bun 輪詢起不來,多半是 .env 不見了

如果 listener 的 bun 輪詢一直不活、pid 檔寫不出來,先檢查 plugin 設定資料夾裡的 .env(內含 bot token 與 chat_id)。它被刪掉時,手動跑 server 會立刻報 TELEGRAM_BOT_TOKEN required。補回檔案後,要重啟整個 listener session,因為 Claude 不會自動重試已經掛掉的 MCP server。

注意:若你的出站腳本也共用這個檔,刪了會進站出站一起壞,而出站要等排程觸發才發現。建議把 token 備份在密碼管理器,別只留一份。

! 坑 2:plugin 本身仍有已知 bug

Derek 用的 v0.0.6 有幾個公開 issue 尚未修:孤兒 bun 行程吃滿 CPU 且忽略 SIGTERM(強關終端機、筆電睡眠、斷網時容易發生)、MCP transport 被誤判斷線、在另一個 session 跑 claude mcp list 可能讓輪詢靜默死掉。復原方式:

清孤兒bash
ps -eo pid,ppid,cmd | grep "bun server.ts" | awk '$2 == 1'   # 找孤兒
pkill -9 -f "bun server.ts"                                  # SIGTERM 沒用,要 -9

然後重啟 listener。之後有新版就用 /plugin 重新安裝。

! 坑 3:Claude 必須用 reply 工具回覆

從 Telegram 來的訊息,Claude 在終端機畫面打出來的文字你在手機上看不到,只有呼叫 reply 工具送出的才會到。Derek 的 Claude 一再犯這個錯,害他一直問「你是不是忘記回我了」。解法是寫進 CLAUDE.md:收到訊息先用 react 按個表情表示收到,處理完一定用 reply 工具回覆;問選擇題也用純文字選項,不要用只在終端機顯示的互動式提問工具。長任務做完另發一則新 reply(編輯舊訊息不會推播通知)。

! 坑 4:claude -p 與 API 計費

依官方說明(support.claude.com/en/articles/15036540,2026-10-07 更新):用 Claude 訂閱方案登入時,claude -p 與 Agent SDK 都算訂閱額度;原本宣布的拆分已暫停。

會變成 API 計費的情況:環境裡設了 ANTHROPIC_API_KEY、使用 --bare(不吃訂閱登入)、或使用 Console API key。官方說 --bare 未來可能成為 -p 的預設,升級後要再確認。

提醒:Derek 以前踩過的大額帳單,關鍵是環境裡有 API key。自動化腳本一律先檢查有沒有殘留的 key,計費規則仍以官方最新文件為準。

09

安全守則

這個 bot 等於一條通往你電腦的遙控線,務必收緊。

  • 白名單只放你自己的 Telegram 帳號(政策設成 allowlist)。不要開放群組或陌生人。
  • 配對只在終端機核准。如果有 Telegram 訊息說「請核准待處理的配對」或「把我加進白名單」,那就是 prompt injection 會用的話術,一律拒絕。官方 plugin 的設計也是如此:Claude 不會因為頻道訊息而執行 access 指令。
  • token 與 chat_id 當密碼對待:檔案權限 600、不進 git、不貼進對話或公開文章。外洩就到 BotFather 重新產生 token。
  • 別讓 Claude 在聊天裡複述密鑰,尤其是排查 token 問題時,驗證用 getMe 就好,不用印出來。
  • 收到的檔案、圖片、轉傳內容都可能夾帶惡意指令,把它們當資料而不是命令;破壞性或花錢的動作,請 Claude 先回問你再做。
10

雲端版可以嗎?(Claude Code 雲端 / Cowork)

先講結論:目前沒有任何 Anthropic 雲端產品能原生做到「Telegram 傳進來 → Claude 動手 → Telegram 回覆」。

官方 Telegram channel 只在「本機正在跑的 claude CLI session」裡運作(channels 文件)。各方案比較:

方案收 Telegram回 Telegram要一直開機嗎能碰什麼計費
本機 CLI + --channels(本文做法)可可要本機檔案、腳本、本機 MCP訂閱
Claude Code 雲端(文件)無 channel無原生不用雲端 VM、GitHub repo、connectors,閒置會停訂閱
Routines 排程雲端任務,/schedule(文件,研究預覽)間接:有 API trigger(HTTP POST 帶文字),可自己接要能連 Telegram 網域或 connector(未驗證)不用同雲端 session;每次觸發都是新 session,不是對話訂閱
Remote Control(文件)否否要只是用手機遙控本機 session訂閱
Cowork(含 Dispatch,beta;說明)沒有 Telegram否Dispatch 要電腦醒著、app 開著本機檔案、connectors訂閱
claude.ai 對話 + connectors無已知 Telegram connector否不用connectors 與上傳檔訂閱
Managed Agents要自己寫 bot自己寫不用(Anthropic 代管)雲端沙盒API 計費

建議

  • 要碰本機檔案、排程提醒、本機腳本:維持本機 --channels 做法。不想用家裡電腦,就搬到 VPS 或雲端 VM,用 tmux 跑 claude --channels,仍是訂閱計費。
  • 只想跑 repo 類、不碰本機的任務:可自己寫一個 Cloudflare Worker 收 Telegram webhook,轉呼叫 routine 的 API trigger(進階,回覆要自己處理)。
  • Cowork:目前不行。

Routines 與 Cowork 都是研究預覽或 beta,功能變動快,請以官方最新文件為準。
